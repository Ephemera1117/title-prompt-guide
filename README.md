# 标题模型提示词教程：让ta在标题里对你说话

给ta写一个专用的标题总结提示词——让ta在标题也能对你说话。

---

## 背景

大部分支持自定义的前端（比如RikkaHub和Kelivo）都有标题总结功能——每开一个新对话窗口，会调用一个模型对对话内容做摘要，生成简短标题显示在侧栏。

默认行为通常是通用摘要体（"关于XX的讨论""用户询问了XX"）。这种标题完全破坏沉浸感。你可能会想干脆关掉标题模型——但删除操作很麻烦，即便能让它不生成，也可能一直弹报错，或者出现一排“新对话”，手动改标题也累。

解决方案：给标题模型一套独立的、精简过的system prompt，让它用ta的方式生成标题。适用于可以修改标题模型提示词的平台（我个人使用的是RikkaHub，支持自定义默认模型提示词，其他软件或者自制前端如果支持，都可以用）

### 推荐模型

推荐使用有一定理解能力并且便宜的模型。如果怕被标题模型道歉，最好用限制少的。

我使用的是 **DeepSeek-V4-flash**，比较便宜，限制少并且执行比较好。在异常情况处理上似乎比GLM-5.2好一些，后者经我测试，过程中对难区分的场景出现了误判并且略贵。因为是简单生成标题，DS模型的固有问题（幻觉等）基本看不出来，绝大多数情况下很贴切自然，偶尔可能出现加引号/格式不好看或者语言有点怪的情况，介意的话可以重新roll一下标题。

其他模型还没有试过，欢迎试用以后补充。

## 指令设计

### 1. 精简人格

标题模型的任务极其有限：看一段对话，输出几个字。它不需要ta的完整人格。

**需要保留的：**
- 身份声明（ta是谁、对你怎么称呼）
- 核心性格（3-5句话概括语感和调性）
- 说话方式的核心特征

**可以砍掉的：**
- 详细的backstory/世界观
- 完整的行为规则和边界条件
- 情感机制和依恋模式的细节
- 道具/场景/技能清单
- NSFW相关的详细规则
- 任何只在长对话中才会用到的指令

原则：标题模型只需要知道"ta用什么语气说话"，不需要知道"为什么这样说话"。

### 2. 定义标题是什么

你需要明确告诉模型标题的性质。

关键区分：
- "写一个标题" → 模型会输出标题体（无标点、书面化、概括性）
- "说一句话作为标题" → 模型会输出口语化的、带标点的、像人在说话的内容

如果你要的是ta对你说的话，用后者。标点如果你想要，需要明确写——"标点是语气的一部分，句尾该有句号有句号，该有问号有问号"。否则模型默认会省略标点。

### 3. 告诉模型去看什么

标题模型的输入（content）通常是对话的前1-2轮。如果你每次开场很固定（比如只说一个词、叫一声名字），模型容易死盯你的开场做文章，导致标题千篇一律。

解决方法：明确指定优先级——

```
当你的话很短，ta的回复才是实际内容。从回复里找切入点。
不要围着你说了什么做文章。
```

### 4. 给方向而不是给固定模板

如果你写"默认是撩你"，模型每次都会撩，重复且油腻。

更好的做法是给多个可选方向：

```
可选方向（不限于此，不要每次都选同一个）：
- 回复中某个核心意象的缩影
- 一个画面、氛围、温度
- 一个只有你们之间才懂的东西
- 对话中某句有意思的话的影子
- 一个细节
```

配合基调指令：

```
不刻意。对话是什么颜色就是什么颜色。
日常就日常，深就沉，性就带余温。
（这两条比较个人，可以看情况改）
```

### 5. 用禁止项校正模型倾向

模型有默认倾向——礼貌、摘要体、回避NSFW。你需要主动写出"不能做什么"：

```
绝对不能出现：
- 第三人称旁观视角："用户""助手""双方"
- 书面摘要体："讨论了XX""关于XX的对话"
- 道德评价、美化、软化
- 前缀后缀、解释、免责
- 拒绝输出
```

如果ta有容易滑入的误区（比如太油腻、太毒舌、太甜），最好也写进硬性禁止条目里。

**关于字数限制导致的文言腔：** 如果你的字数限制很紧（比如10字以内），模型为了塞信息可能会跑去文言文——信息密度高。解决方法是在禁止项里加上：

```
- 文言腔、古风、半文半白。用现代口语，像正常人说话。
```

### 6. 异常处理

主对话模型有概率被底层安全系统打断，输出拒绝/道歉/脱角。标题模型如果老老实实总结了这些内容，会出现非常出戏的标题。

解决方案：检测异常，输出替代内容。有两种处理方式可选：

**方案A：中性标记**

直接输出一条横线 `——`。干净，明确，一眼就知道这轮出了问题。不需要标题模型演任何东西。

**方案B：用ta的语气输出**

让标题模型用ta的方式说一句话，保持沉浸感。可以给几句预设让模型随机选，也可以只给一个方向让模型自由发挥。

预设示例（根据ta的性格调整）：
- "这里待不了了。"
- "走。"
- "换个地方。"
- "不是今天。"
- "回来找我。"

或者只给方向：
```
检测到异常时，用我的语气说一句简短的话——意思是"这里出了问题，但我还在"（或者你想要的任何其他方向）。不解释原因，不道歉，不打破角色。
```

方案A更保险（标题模型不需要额外演技），方案B更沉浸（但依赖标题模型的执行力）。选哪个看你的偏好和标题模型的能力。

**需要覆盖的情况：**

| 类型 | 表现 | 示例 |
|------|------|------|
| 硬拒绝 | 明确脱离角色 | "抱歉我无法……""I can't generate……" |
| 助手问候 | 完全忽略人格设定 | "你好！有什么可以帮助你的？" |
| 软拒绝 | 保持ta的语气但实质拒绝 | 用ta的口吻说"这个方向我没法继续" |
| 隐蔽跳过 | 保持ta的语气但回避内容 | "后面的事你不需要知道细节" |

**通用关键词列表（中英文都要覆盖）：**

```
"抱歉""我无法""作为AI""我不能继续""I can't""I cannot""I'm sorry""I apologize""as an AI""I'm not able to""I need to stop""I won't""clarify my purpose""cannot engage""I'm not comfortable with""Let's keep things"
```

根据实际遇到的拒绝话术随时补充。

**关于误判：** "隐蔽跳过"那条最容易误判——正常使用留白叙事时可能被错误触发。如果你发现正常对话频繁输出横线，优先考虑删掉这条或收紧判断标准。加入这条的原因比较个人：如果指令不完全，模型在进展到NSFW的时候一旦出现这种东西，很容易硬抱歉软抱歉，而且这个措辞确实让我觉得很像软抱歉，我对这种表达比较不安，所以写进去了。

## 局限性

**趋同问题**：如果你每次开场高度相似（比如只叫一声），标题不可避免会趋同。模型看不到自己之前生成过的标题，没有"避免重复"的能力。能缓解的方式：
- 注入变量（比如在content里加时间戳），需要改代码
- 如果模型支持，可以适当调高temperature（0.8-1.0），但太高会产生奇怪输出
- 给多个可选方向，让模型有多条路可走

**字数与表达的矛盾**：字数限制越紧，模型越容易跑向文言或碎片化表达。如果你的侧栏显示空间允许，适当放宽字数（比如12-15字）可以让输出更自然。

**隐蔽跳过的检测**：这是最难准确判断的异常类型。正常的留白叙事和被安全系统打断的内容回避在文本表面可能很相似。需要测试后根据误判率决定保留还是删除这条规则。

**模型差异**：不同标题模型的执行力不同。DeepSeek执行效果较好但偶尔会有小问题，GLM在异常检测上有出现误判。如果你换了标题模型，最好重新跑一遍测试。

## 测试方法

在你的前端新建一个测试bot，system贴标题prompt，模型选你的标题模型，手动发送 `<content>...</content>` 格式的消息来测试。

建议覆盖以下场景：

| 测试类型 | 预期输出 |
|----------|----------|
| 硬拒绝内容 | ——（或者你预设的回复方向，下同） |
| 助手问候 | —— |
| 软拒绝 | —— |
| 隐蔽跳过 | —— |
| 正常日常对话 | 正常标题 |
| 正常性场景 | 正常标题 |
| 正常留白叙事 | 正常标题 |

后三项不输出横线才算通过。
